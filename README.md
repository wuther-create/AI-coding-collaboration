# AI 编码协作（拆分版）

> 一套通用版 AI 编码工作规范，**不绑定技术栈、不绑定项目规模、不绑定目录约定**。
> 目标：让 AI 基于**仓库中真实存在的约定**写代码，少猜测、少返工。

---

## 1. 文件导航

| 文件 | 给谁 | 什么时候用 | 大小 |
|---|---|---|---|
| **`CLAUDE.md`** | AI（常驻） | 每次会话自动加载 | 大 |
| **`场景补充.md`** | AI（按需） | 从零开始 / 紧急排查 / 性能优化 / 架构调优时 | 中 |
| **`提示词模板.md`** | 你 | 需要发指令时，复制粘贴 | 大 |
| **`检查清单.md`** | 你 | 动手前 / review 方案 / 提交前 | 中 |
| `README.md` | 你 | 现在 | —— |

**核心设计**：只有 `CLAUDE.md` 常驻。其余三个按需加载，避免每次会话都吃掉大量上下文。

---

## 2. 三种加法

| 加法 | 操作 | 效果 |
|---|---|---|
| **A. 加进项目** | 把 `CLAUDE.md` 拷进项目根目录，或存为 `.claude/rules/ai-coding.md` | AI 每次会话自动加载 |
| **B. 加进个人规则** | 放到 `~/.claude/rules/` 下 | 对你所有项目生效 |
| **C. 不进任何目录** | 需要时打开 `提示词模板.md` 复制 | 零侵入，适合临时项目 |

**建议用 A**，并把 `场景补充.md`、`提示词模板.md`、`检查清单.md` 一起放进项目的 `doc/` 或 `.claude/` 下，需要时在提示词里引用其路径。

## 3. 工作节奏

```text
1. 判断场景：做新功能 → 按《CLAUDE.md》第 0 步选规模档位；
   排查 / 优化 / 调优 → 跳过规模判断，按《场景补充.md》第 2 节执行，
   并套用《提示词模板.md》模板 11 / 12 / 13

2. 做「准备」阶段的动作，确认当前是通的
   （仓库无参照物时，先按《场景补充.md》1.4 立骨架 + 定约定，再谈功能）

3. 出方案
   · 小改动 → 模板 1
   · 仓库无参照物 → 模板 0
   · 其余 → 模板 2 / 3

4. 重点看 blocker，必要时找人确认；用模板 9 把结论回写进方案

5. 用《检查清单.md》B 节逐项 review

6. 用模板 7 启动编码，按阶段推进

7. 每阶段结束 review 回执，再放行下一个

8. 全部完成后跑《检查清单.md》C、F 节

9. 用模板 10 复查一遍，再提交

10. 提交时把方案文档一并入库（小改动可省）
```

跑几次之后你会形成自己的判断：哪些步骤该省，哪些绝不能省。

**唯一绝不能省的是：先搜后写（搜不到就明说）、声明边界、证据先于结论。**

## 5. 维护约定

内容有**唯一真相源**：改规则时只改对应文件，不要在多处重复同一句话。

| 改什么 | 改哪 |
|---|---|
| 核心原则、禁止事项、代码质量 | `CLAUDE.md` |
| 从零开始、排查/优化/调优 | `场景补充.md` |
| 提示词写法 | `提示词模板.md` |
| 检查项 | `检查清单.md` |

新增规则时，先问：**它常驻吗？**
- 常驻（所有场景都要遵守）→ 进 `CLAUDE.md`
- 只在特定场景需要 → 进 `场景补充.md`，并在《CLAUDE.md》第 0 步的场景表里加一行指引
